# S0 · 度量与门禁 — 工作方案（2026-11-18）

> **状态**：方案定稿，待逐项实施。
> **依据**：本目录 `../WE3D-下一步开发方向分析与建议-20261118.md` §一/§四方向4/§五 8.1/8.3/8.4/§六/§八，`design/appraisal/WE3D-独立项目评估-20261118.md` §八 P0，`AGENTS.md` §三。
> **定位**：**地基阶段，尽量不改变视觉**。让「改完有没有变好、有没有回归」变成可回答、可复现的问题；S2/S3 的一切渲染改动都依赖本阶段建立的度量与门禁。

---

## 一、目标与范围

**一句话目标**：把「无度量、软门禁、边界名不副实」转成「有可复现数据、硬门禁、导出零新增漂移」。

| 维度 | 起点（2026-11-18 实测） | S0 终点 |
| --- | --- | --- |
| 性能可观测性 | `timestamp-query` 仅 `scene.ts:139` 请求，零查询实现；无 drawcall / bandwidth 统计；无 perf spec | GPU timestamp profiler + CPU/DC 统计 + 可复现 perf harness + 报告 |
| 公共 API | barrel 256 / 实际 666，410 游离导出，`check:exports` 仅告警 | 新增导出零漂移（ratchet 阻断）；存量 410 完成分类 |
| 回归防线 | e2e 基线缺失已硬失败、skip 已清零、console 已硬断言（`e4d76a2`）；无覆盖率阈值 | 覆盖率阈值落地；上述硬门禁不回退；e2e 仅本地 |
| 产品化 | 无根 LICENSE / CHANGELOG；无 tag；README 双包名不一致 | 三件套齐备，决策项拍板后闭环 |

### 用户拍板对本阶段的约束（必须遵守）

- **D3**：性能**对照口径暂不拍板**，推迟到 demo 对比阶段结合 PBR 材质优化确定。S0 **只建度量能力**（harness + timestamp-query），**不预设** IBL-only / N 光双口径为最终指标；可以保留「同资产/同相机/同分辨率/同光照」的可复现实验骨架，但阈值留空。
- **D7**：**不引入云端 e2e / perf 门槛**——GitHub 端无硬件 GPU 且有问题，e2e 只在本地机。所有门禁设计不得依赖云端 e2e。
- **D1**：既有 PBR **目前不冻结**（仅 bugfix），冻结推迟到 S1。S0 不得改动 `PBR.fs.wgsl` / `PBRMaterial.ts` 的既有行为。
- **并行规则**：S0 的产品化子项可与任何阶段并行；其余时刻最多一条渲染改动主线。

## 二、任务清单

按依赖与风险排序。`S0-A/B` 不改视觉、不动 GPU 基线；`S0-E` 触碰渲染路径，须走 `test:baseline` + `ci`。

### S0-A · 性能可观测性与基准体系（P0，核心）

| 项 | 内容 | 交付物 | 验收 |
| --- | --- | --- | --- |
| A1 | GPU timestamp-query profiler：`createQuerySet` / `writeTimestamp` / `resolveQuerySet` + `MAP_READ` 回读；feature 缺失时优雅降级（保留 CPU-only 报告） | `src/we/core/.../gpuProfiler.ts`（位置实施时定）+ 单测 / browser 测试 | 真实 device 上可拿到逐 pass GPU 帧时间；无 feature 时不报错 |
| A2 | CPU/DC 统计：CPU frame time、drawcall 数、pipeline 命中率、WGSL 拼接/MD5 次数、每帧 lights uniform 上传量 | 运行时统计模块 + 读取入口 | 单帧统计可打印/可导出，字段语义有注释 |
| A3 | perf harness（可复现骨架）：固定资产/相机/分辨率/光照配置，输出 CPU/GPU frame time、drawcall、带宽/显存 | harness 脚本或 browser spec + 报告样例 | 同机连续两次运行，误差区间有明确记录；报告不含 30%/70% 占用率口径 |
| A4 | perf spec 基线：把 A3 的报告固化为可比对基线（不设通过阈值，仅记录） | `tests/perf/` 或 `design/.../s0/perf-baseline.md`（实施时定） | 报告可复现、可 diff |

> A1–A2 是 S3 clustered culling 等优化的验收前提；A3–A4 只建立「能测」，不回答「比 three.js 快多少」（后者按 D3 推迟）。

### S0-B · 公共 API 边界门禁（P0，可并行）

| 项 | 内容 | 交付物 | 验收 |
| --- | --- | --- | --- |
| B1 | `check:exports` 从「仅告警」升级为 ratchet：一次性登记当前 410 个游离导出为基线，此后**新增且未入 barrel** 的导出硬失败；提供显式刷新脚本（仿 `quality:baseline`） | `scripts/export-baseline.json`、`scripts/check-exports.mjs` 改造、`package.json` 新增 `exports:baseline` | 新增一个未入 barrel 的导出时 `check:exports` 非 0 退出；存量 410 不阻断；刷新后基线收紧 |
| B2 | 存量 410 个游离导出分类：核心类型补入 barrel / 明确标为内部（约定或路径隔离） | 分类清单 + 逐批补入的 barrel 改动 | 分类完成、barrel 符号数上升有据；`check:exports` 全绿 |

> B1 是本阶段第一个可立即落地的子项，且不需要任何产品决策。B2 涉及公共 API 语义，**补入 barrel 的类型需逐个确认**（不盲目全量纳入）。

## 三、执行顺序与批次

```
批次 1（无决策、不改视觉）
  B1 check:exports ratchet  →  C1 门禁复核  →  C3 基线归因
批次 2（度量地基）
  A1 timestamp profiler  →  A2 CPU/DC 统计  →  A3/A4 perf harness + 基线
批次 3（分类与阈值）
  B2 导出分类（逐批确认）  →  B3 导入约束  →  C2 覆盖率阈值
批次 4（产品化，需拍板）
  D1/D4 拍板 → D2 CHANGELOG → D3 授权打 tag
批次 5（可选，需基线）
  E1/E2 —— 仅在 A3 证明必要时启动
```

**门禁策略**：每批次结束跑 `npm run ci:no-e2e`；涉及渲染（A1 若改渲染路径、E1/E2）先 `npm run test:baseline` 再 `npm run ci`。提交格式遵循 `AGENTS.md` §六（`MMDD 具体内容`），提交前全绿。

## 四、退出条件（硬性，缺一不可）

1. `npm run ci:no-e2e` 与本地 `npm run ci` 全绿；既有 GPU 基线零漂移（e2e 仅本地、不依赖云端）。
2. perf 报告可复现：同机两次运行的误差有明确区间；报告不含 30%/70% 占用率。
3. 新增导出零漂移：`check:exports` 对新增游离导出硬失败；存量 410 分类完成。
4. 覆盖率阈值生效且主路径覆盖有基线。
5. 产品化三件套闭环，决策项（D1/D4 拍板、D3 授权）已落地。

- 不冻结既有 PBR（D1，推迟到 S1）；不改 `PBR.fs.wgsl` / `PBRMaterial.ts` 既有行为。
- 不预设性能对照口径、不与 three.js 做快慢结论（D3，推迟到 demo 对比）。
- 不引入云端 e2e / perf 门槛（D7）。

- 不打 tag、不发布、不改许可证类型，除非用户明确授权/拍板。

### A1–A4 实施记录（2026-11-24）

- **A1**：`src/we/core/profile/gpuProfiler.ts`。WebGPU 已移除 `writeTimestamp`，改为 pass 描述符 `timestampWrites`；profiler 提供 `stampRenderPass/stampComputePass`（未启用时返回原描述符）、`resolve()`（querySet→resolve buffer→read buffer）、`read()`（BigUint64Array 纳秒转毫秒）。默认关闭、feature 缺失 no-op，不改任何绘制/纹理/相机，GPU 基线零改动。
- **A2**：`src/we/core/profile/frameStats.ts`。进程内单例收集 CPU 帧墙钟耗时、drawcall、compute dispatch、缓存命中/未命中、WGSL MD5 次数、灯光/阴影 uniform 上传字节。计数点：`BaseDrawCommand`/`SimpleDrawCommand` 的 `drawInstacnce`、`ComputeCommand.dispatchWorkgroups`、`AssetCache.acquire`、`DrawCommandGenerator` 两处 MD5、`LightsManager` 两处 writeBuffer、`Scene.run()` 帧边界。
- **A3/A4**：harness = `gpuProfiler.browser.test.ts` 的「perf harness 骨架」用例；报告结构与口径见 `perf-baseline.md`。遵守 D3：不设阈值、不写 30%/70% 占用率、不做 vs three.js 结论。
- **验证**：`npm run typecheck` 通过；`frameStats.test.ts` 5/5；`gpuProfiler.browser.test.ts` 4/4（真实 device）；`npm run ci:no-e2e` 全绿（node 169 / browser 80）；`npm run test:e2e` **90 passed** —— GPU 基线零漂移，证实 profiler 默认关闭 + 计数点不改像素。
