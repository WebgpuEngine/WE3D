## 一、目标与范围

**一句话目标**：把「现有 PBR 已被 90 张基线 + 5 renderMode + `materialKind=1` 锁死、glTF 材质扩展零消费点、光照是 PBR/Phong 双份内联实现」的现状，收敛为一份可据此直接进入 S2 实施的冻结契约。

| 维度 | 起点（2026-11-27 实测） | S1 终点 |
| --- | --- | --- |
| 材质模型 | 单一 `PBRMaterial`（`material/PBR/PBRMaterial.ts`，直接继承 `BaseMaterial`），5 个别名 `material.pbr.{forward,defer,Msaa,MsaaInfo,blend}`；无 `GltfPBRMaterial` 层 | 新材质族 `GltfPBRMaterial` + `material.gltfPbr.*` 的完整契约（schema/feature/uniform/bindgroup/变体），与 legacy 边界清晰 |
| glTF 消费点 | glTF 材质复用 `PBRMaterial`（`gltfMaterials.ts:265`），`materials[].extensions` 从不读，`KHR_materials_*` 全系零实现，`extensionsRequired` 无校验 | 唯一消费点 `GltfMaterialParser` + 扩展分批（A/B/C）每扩展的 feature/消费点/参考模型/验收口径；`extensionsRequired` 硬校验语义 |
| 变体机制 | SHR 别名 + pipeline LRU(60)；`PBR.fs.wgsl` 12 组 `if(kind)` 参数分支、`deferRender.fs.wgsl` 内联 PBR+Phong 双分支 | feature mask → 变体 key 的编码规范 + 组合上限 + fallback + 共享 BRDF include 划分 |
| 光照/阴影 | `LightsManager` + `st_light`（dir/point/spot）+ PCSS 三光源；shadowmap 固定 1024²、每灯 6 面预留；无光剔除 | 光源语义统一 + 剔除方案（CPU/GPU 分界、前向/延迟共用）+ shadow 动态化演进路径 + `materialKind` 分配 |
| 契约/API | group0/1/2/3 手动布局 + 动态 `@group(2)` 注入；barrel 272 / 游离 410（ratchet 已生效） | 新材质族 bindgroup 契约、公共 API 清单、基线策略定稿 |

**强制引用规则**

1. 每个 glTF 相关 RFC 条目须有「官方出处」栏，填写 `O1 §x.y` / `O2 KHR_xxx` / `O3 API.md` 等精确引用；无出处者标记「待查」，不得进入冻结。
2. 项目内文档（方向分析、`gltf-extension-dependency.md` 等）与官方来源冲突时，**一律以官方为准**，并在 RFC 记录冲突点与偏离理由（有意偏离也须说明）。
3. 官方扩展支持与否以 O2 状态 + O4 列表为准；本项目的「支持 / 不支持 / 推迟」须逐项对照 O4 的 32 项全集（D2 取舍表），不得仅凭项目内文档自定。
4. 官方截图（O5）是视觉参考，不是可严格复现的基线；若作为验收基线，RFC 必须定义相机 / 环境 / 曝光的来源（D4 的 JS 对齐要求）并记录差异口径。
5. 引用须可追溯：RFC 中每个官方出处在 F1 核对时按本节 URL 复核一次；URL 或章节号错误视为核对失败。
6. **获取渠道不限**：正常 web 获取（官方文档 / 示例 / 在线 URL）与 `local-reference-library.md` 的本地镜像**均有效**，按网络条件自行选择；本地镜像只是加速手段、非强制前置。无论哪种渠道，引用必须是官方一手来源，在线 URL 保持可追溯。

**核对结论（2026-11-27，原方案的 4 类缺口，已按下表落点修正）**

| 官方出处 | 必须落到 RFC 的约束 | 当前方案落点 | 核对结论 |
| --- | --- | --- | --- |
| §3.9.2 / §5.19.4 Metallic-Roughness | `factor × texture` 为线性乘；`baseColorTexture` 8-bit sRGB 且计算前解码到线性；`metallicRoughnessTexture` G=roughness、B=metalness 且 linear；`F0=0.04`；`COLOR_0` 为额外线性乘数 | A1 | **缺**：原 A1 只写「核心 MR」，未列数值口径 |
| §3.9.3 Normal/Occlusion/Emissive | normal 先 scale 后归一化、blue∈(0.5,1]；occlusion 红通道 `occlusion=1+strength*(tex-1)`；emissive 8-bit sRGB，乘积单位 cd/m² | A1 | **缺**：同上 |
| §3.9.4–5 `alphaMode` / `doubleSided` | `OPAQUE`/`MASK`/`BLEND` + `alphaCutoff`（仅 MASK 生效）；BLEND 用 over operator；doubleSided 时背面法线光照前 MUST 反转 | A1 + D5（新增） | **缺**：原方案 9 主题未显式覆盖 alpha/doubleSided |
| §3.9.6 Default Material | mesh 无 `material` 时用全默认值的 default material | A2 | **缺**：消费点未定义缺省行为 |
| §3.8 纹理数据 / §5.29–5.30 Texture Info | sampler wrapS/wrapT/minFilter/magFilter；`texCoord` ST 原点左上；PNG/JPEG 的 ICC/gamma 信息 MUST 忽略；每个 textureInfo 可带 `extensions`（transform 挂点） | A1 + D3 | **缺**：未列纹理采样/色彩空间口径 |
| §3.12 / §5.17.1–2 extensions | `extensionsRequired ⊆ extensionsUsed`；required 未支持时 SHOULD NOT be loaded（§3.2 同口径）；glTF 对象（asset/material/texture/pbrMetallicRoughness 等）均可挂 `extensions` | D1 + A2 | 方向正确，需补精确语义 |
| §3.10 Cameras / §3.7.2.2 Morph / §3.7.2.1 JOINTS_n·WEIGHTS_n | **均为核心规范，不是 KHR 扩展**；morph 公式 `A'_i=A_i+ΣΔA·W`，morph TANGENT 用 VEC3；`extensionsRequired` 是规范机制而非扩展 | A2 / D2（分类修正） | **概念错误**：原 P7 把 cameras/morph/JOINTS/extensionsRequired 写成「批 A 扩展项」 |
| Appendix B BRDF Implementation | B.1 General / B.2 Material Structure（B.3 Sample Implementation 为 Informative）是 glTF PBR 数值参考；规范允许不同实现（device/resource），但**可核对的官方实现只有这一份** | B3（新增 oracle） | **缺**：原 B3 只写「共享 BRDF include」，未绑定官方附录 |
| KHR_materials_unlit README（Ratified） | unlit 仍以 `pbrMetallicRoughness.baseColor*` + vertexColor 为输入，保留 alpha coverage 与 doubleSided，忽略其余 PBR 属性；对象为空、布尔开关；不支持时回退 PBR | D3 | **需修正**：原「unlit → ColorMaterial 路径映射」会丢掉 alpha/doubleSided/vertexColor 语义 |
| glTF-Sample-Viewer / Sample-Assets | 官方 viewer 支持 32 个 KHR 扩展（材质类 16 个）；资产截图在 `Models/<Name>/screenshot/screenshot.jpg`，但**README 未给统一相机/HDRI/渲染参数**——截图是视觉参考，不是可严格复现的基线 | D2 + E3 | **需修正**：原 E3 把官方截图当基线前，必须定义「相机/环境/曝光」的可复现来源（D4 的 JS 对齐要求） |

> 核对方法：本轮（2026-11-27）通过在线 URL 定位缺口，结论见下表；后续 RFC 写作可通过正常 web 获取或 `local-reference-library.md` 的本地镜像逐条复核并更新勾稽状态，两种渠道均不受限（规则 6）。

### 用户拍板对本阶段的约束（必须遵守）

- **D1**：既有 PBR 到 **S1 才冻结为 legacy**——本阶段交付物必须**定死 legacy 冻结边界**（锁定哪些文件/别名/`materialKind`，只收 bugfix 的白名单口径）；S1 本身不改 `PBRMaterial.ts` / `PBR.fs.wgsl` 的既有行为。
- **D2**：`GltfPBRMaterial` 成为 glTF 默认材质的时点 = 批 A 完成 + 核心 MR 模型与 legacy 像素对齐后（S2 执行）；S1 只定契约与切换判据，不切换。
- **D3**：性能对照口径暂不拍板，推迟到 demo 对比阶段；S1 不预设 IBL-only / N 光双口径为最终指标。
- **D4**：官方 GLSL 扩展实现**以原理参考为主**（不直译、不 vendor）；样本资产 + 截图基线可用但须一并对齐官方资产/相机等 JS。S1 在扩展分批中给出「参考模型 → WGSL feature → 参考语义」的映射表，不搬 GLSL。
- **D7**：不引入云端 e2e/perf 门槛，e2e 仅本地。

## 二、任务清单

RFC 拆为五个工作组（S1-A ~ S1-E）+ 评审定稿（S1-F）。每项交付物均为 `s1/` 下的 RFC 章节，验收是「可被 S2 直接据此实施」的判据，而非「设计得好」。

### S1-A · 材质 schema 与 feature 体系（核心）

| 项 | 内容 | 交付物 | 验收 |
| --- | --- | --- | --- |
| A1 | 统一材质参数 schema：参数描述（字段/类型/单位/默认值/取值范围/所属 feature）。**必须逐字段覆盖官方 §5.19 的 11 个 Material 字段**（`pbrMetallicRoughness` 的 5 子字段、`normalTexture`/`occlusionTexture`/`emissiveTexture`/`emissiveFactor`、`alphaMode`/`alphaCutoff`/`doubleSided`）＋§3.9 数值口径（sRGB 解码、线性乘链、`F0=0.04`、normal 归一化、occlusion 公式、emissive cd/m²）＋批 B 扩展 | RFC §材质 schema + 示例 + **官方字段勾稽表** | 逐字段勾稽官方 §5.19 无遗漏；每字段有默认值/取值范围/色彩空间；可用 JSON 表示（供 S5 编辑器反射）；**不得以「现有 PBR 参数」为覆盖标准** |
| A2 | 唯一消费点设计：`GltfMaterialParser`（glTF JSON → 规范化 description）的输入/输出/错误语义；与 `GltfDataAtTransform` 的边界；**明确 §3.9.6 Default Material、§3.10 cameras、§3.7.2.2 morph、§3.7.2.1 JOINTS/WEIGHTS 的核心规范消费路径（不归为扩展）** | RFC §消费点 + 数据流图 | 明确「谁读 `materials[].extensions`、产出什么、谁消费」；缺省 material/camera/morph/joints 语义与官方一致；`extensionsRequired` 校验挂在此处；与 `gltfTransformLoaders.ts` 边界清晰 |
| A3 | feature set 与 feature mask 编码：feature 命名空间、mask 位宽与分配、OpenPBR 扩展位预留 | RFC §feature mask | 每 feature 有唯一 mask 位；mask 可确定性 hash 成变体 key；OpenPBR 位预留但零实现 |

| D5（新增） | alphaMode（OPAQUE/MASK/BLEND）+ alphaCutoff + doubleSided 的管线契约：MASK 的 cutoff 仅生效于该模式、BLEND 用 over operator、doubleSided 背面法线光照前反转；正反面渲染模式与 pipeline 变体的关系 | RFC §alpha 与双面 | 三模式逐项对齐 §3.9.4–5；与 B1 变体 key 的 `renderMode` 维度衔接；有官方出处 |

**D2 官方 32 项取舍表 · 两期划分（用户 2026-11-27 拍板）**

- **第一期（S1 冻结硬约束，必须逐项做完）**：材质类 16 项 `KHR_materials_*` —— 逐项标注 `支持 / Unsupported / 推迟` + 理由 + 官方 README（O2）出处；其中 `KHR_materials_pbrSpecularGlossiness` 须额外标注 Archived 状态；逐项给出 S2/S3 支持顺序建议。
- **第二期（不阻塞 S1 冻结，S2/S3 实施前补齐）**：其余 16 项非材质扩展（texture / lights / 压缩 / 动画 / 节点 / 物理 / XMP 等）逐项同样标注与给出官方出处。
- 核心规范特性（cameras / morph / JOINTS / `extensionsRequired`）另列，不计入 KHR 扩展分批。
- **取舍表只判定「支持与否 + 顺序」，不等于实现 16 项扩展**；实现范围仍按批 A/B/C 与 S2/S3 阶段目标。
