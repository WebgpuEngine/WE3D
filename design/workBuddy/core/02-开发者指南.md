> 目标读者：用 WE3D 写业务的人。

> 字段级细节查 [03-API速查手册](./03-API速查手册.md)；想改内核先看 [01-设计思路](./01-设计思路.md)。

## 一、环境与启动

```bash
npm install
npm run dev        # vite dev server
npm run build      # tsc && vite build
npm run examples:generate    # 重新生成 examples/files.json 索引
```

**浏览器要求**：需支持 WebGPU（Chrome / Edge 113+，Safari 26+）。**引擎没有 `navigator.gpu` 的能力检测提示页**——不支持的浏览器会直接报错白屏，这是当前的已知缺口（见 [04 P1-9](./04-问题缺陷与改进建议.md)）。

**运行示例**：每个示例是成对的 `xxx.html` + `xxx.ts`，vite dev 下直接访问 `http://localhost:5173/examples/.../xxx.html`。

> `examples/index.html` **不是**手写索引——它是 SPA 外壳，运行时 `fetch('files.json')` + `fetch('tags.json')` 渲染侧边栏与 iframe 预览。
> 各**二级**目录的 `index.html`（如 `examples/system/index.html`）才是手工维护的链接页，新增示例后记得同步。

## 二、通用骨架模板

绝大多数示例都是下面这个形状（摘自 `examples/system/postprocess/FXAA.ts`、`examples/system/pickup/renderModel/sphere.ts`）：

```ts
import { IV_Scene } from "../../../src/we/core/scene/base";
import { initScene } from "../../../src/we/core/scene/fn";
import { PerspectiveCamera } from "../../../src/we/core/camera/perspectiveCamera";

declare global { interface Window { scene: any; DC: any } }   // 全局调试用

// 1、场景配置 —— 唯一必填项是 canvas
let input: IV_Scene = {
  canvas: "render",
  backgroudColor: [0, 0, 0, 0.2],
  reversedZ: true,                       // 反向 Z，深度精度更好，推荐开启
  toneMapping: E_ToneMappingType.linear, // 可选
};
let scene = await initScene({ initConfig: input });
window.scene = scene;                    // 挂到 window，方便控制台调试

// 2、相机（controlType 直接内置控制器，不需要新建 Control 对象）
let camera = new PerspectiveCamera({
  fov: (2 * Math.PI) / 5,
  aspect: scene.aspect,
  near: 0.01,
  far: 100,
  position: [0, 0, 3],
  lookAt: [0, 0, 0],
  controlType: "arcball",                // "arcball" | "wasd" | "orbit"
});
await scene.add(camera);

// 3、实体
let mesh = new Mesh({
  attributes: { geometry: new BoxGeometry() },
  material: new ColorMaterial({ color: [0, 0.1, 0.2, 1] }),
});
await scene.add(mesh);
```

### 三条必须记住的约定

| 约定 | 说明 |
| --- | --- |
| **顶层 `await`** | 示例都是 `<script type="module">` + 顶层 await，不需要包 `async function`（vite 配了 `vite-plugin-top-level-await`） |
| **不要手动 `scene.run()`** | `initScene()` 内部已自动调用（`scene/fn.ts:17-21`）。只有 NDC / 手工提交 DC 的示例才传 `runImmediately: false` 再手动 `dc.submit()` + `scene.renderToSurface()`（见 `examples/system/00_NDC/01_NDC_1_triangle.ts`） |
| **一切都要 `await scene.add(...)`** | 相机、光源、实体、模型、后处理都走 `scene.add`，返回 `Promise<NodeObject>` |

### 更底层的写法（绕过 initScene）

`examples/base/00_scene/b1.ts` 展示了最小写法：

```ts
let scene = new Scene(input);
await scene._init();          // 注意：这里不会自动 run()
```

## 五、常见坑（Top 15）

> 症状 → 原因 → 解决。标 **[核]** 的已在源码中定位到具体行。

| # | 症状 | 原因 | 解决 |
| --- | :--- | --- | --- |
| 1 | 画面全黑 | 没加光源也没加 AmbientLight | PBR/Phong 材质需要光；或先用 `ColorMaterial` 排查 |
| 2 | 透明物体发黑 / 有黑边 | `premultipliedAlpha` 用错 | 标准混合需预乘；非预乘混合不要预乘。见 `texture/base.ts:57-75` 的详细说明 |
| 3 | 模型渲染出来是纯金属 | glTF 的 `metallicFactor: 0` 被 `\|\| 1` 吞掉 | 见 [../03-gltf模块深度分析.md](../03-gltf模块深度分析.md) D7 |
| 4 | **[核]** 删除对象后显存不降 | `RootGPU.destroy()` 第 138 行删的是 map 名不是 key | `organization/root.ts:138`；临时方案：在 `_destroy()` 里手动删 |
| 5 | **[核]** 输入事件被 UI 和相机同时响应 | `intercept` 优先级判定把下标数字与字符串枚举比较，永假 | `input/inputManager.ts:300/314/334/351/366/378`；临时方案：自己在回调里判断并 return |
| 6 | 加了 10 个光源只有 8 个生效 | `V_lightNumber = 8` | `base/coreDefine.ts:102`；改这个值需要同步 shader |
| 7 | 多 primitive 的 glTF 只显示一部分 | entity Map 的 key 用了 mesh 索引 | `model/gltf/gltf.ts:1175`；见 gltf 文档 D1 |
| 8 | Resize 后第一帧卡一下 | `resourcesGPU.clean()` 使全部 pipeline/shader 缓存失效重建 | 正常行为，`scene.ts:777` |
| 9 | 自定义 shader 报 location 不匹配 | 未遵守 group0~3 约定，`@location` 与顶点属性推断不一致 | 参考 `DrawCommandGenerator.ts:543` 的 `formatLocationStringOfAttribute` |
| 10 |  uniforms 改了没生效 | 写的是 CPU 视图，依赖 `BOL.update()` 刷到 GPU | 确认 pointer 来自 `scene.pointers.createPointer`，且调用了 `updatePointerData` |
| 11 | 子对象没跟着父对象动 | `DirectInWorldSpace = true` 会跳过 matrixWorld 合成 | `nodeObject.ts:199-206` |
| 12 | 旋转结果与预期相反 | Node 同时支持欧拉角与四元数，**四元数优先** | `nodeSpace.ts:307-311`；二者不要同时设 |
| 13 | 纹理上下颠倒 | `upsideDownY` 默认 true | `texture/base.ts:77-80` |
| 14 | Draco 模型加载异常 | 依赖本地 fork 的 loaders.gl dist 补丁 | 见 [../04-迁移到glTF-Transform方案.md](../04-迁移到glTF-Transform方案.md) |

## 七、扩展指南

### 7.1 新增自定义 Manager / 全局系统

不需要改 `Scene`——塞进 FeatureManager：

```ts
class MySystem extends FeatureClass {     // organization/featureClass.ts:8
  async update(clock: Clock) { /* ... */ }
}
scene.otherManager.add(mySystem);          // scene.otherManager 即 FeatureManager
```
FeatureManager 会在 `update:828`、resize 时自动调用。

### 7.2 新增自定义材质

1. 继承 `BaseStandardMaterial`（`material/standard/baseStandard.ts`）；
2. 实现 `readyForGPU()` / `_writeUniformCommon()` / `update()`；
3. **必须按 group0~3 约定放置 bindGroup**，否则会丢失 IBL / 拾取 / 延迟渲染支持；
4. 在 `SHR` 注册自己的 shader code（`addShaderCode`）。

### 7.3 新增自定义实体

继承 `EntityBundleMaterial`（`entity/entityBundleMaterial.ts`），设置 `kind = E_entityType.xxx`，必要时在 `E_entityType`（`entity/base.ts:9-16`）加成员。

### 7.4 动态顶点数据

```ts
new Mesh({
  attributes: { data: { vertices: { position: number[] } } },
  dynamicAttribute: true,     // 走 dynamicVS 路径，用单独 GPUBuffer 而非 BOL pointer
});
```
⚠️ `drawMode` 不可变（有索引 / 无索引不能中途切换），且只支持 `number[]` 类型（`entity/base.ts:147-157`）。
