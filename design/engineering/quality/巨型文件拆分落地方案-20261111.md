## 二、「一次完整 CI」的精确定义

`npm run ci`（package.json L48）**不含 `test:browser`**，而 `ci:no-e2e`（L49）含但不含 e2e。总方案 §2.6 已把「glTF 契约 66 项 browser 测试不在 `ci` 链路」列为缺口，而第 3 期恰好要拆 `gltf.ts`。因此定义：

```
完整 CI = npm run ci:no-e2e && npm run test:e2e
        = lint + check:quality + typecheck + test:run(92) + test:browser(73, 含 glTF 契约 66)
          + check:exports + build:lib + test:e2e(85, GPU 逐帧差值)
```

等价于 `npm run ci` 再补 `test:browser`。每次拆分提交都按此跑一遍。
e2e 默认 8 workers 已知偶发页面加载超时（总方案 §五 第 2 期记录）：若**仅**超时类失败，用 `npx playwright test --workers=4` 复验并在执行记录中注明；若出现截图差值，一律按缺陷处理。

## 三、通用拆分机制（零 API 漂移）

实测前提：`src/we` 全量扫描 `private|protected` 仅 3 个文件命中，这 8 个文件**内部 0 处**——所有成员都是 TS 默认 `public`。因此搬走实现后类内必须保留**同名同签名**的方法壳。

1. **类型/接口/枚举/常量/纯函数块** → 同目录新模块 `xxx.ts`；原文件用
   - `export { A, B } from './xxx'`（运行时值：enum / function / const）
   - `export type { C, D } from './xxx'`（interface / type，index.ts 头部注释明确要求分开，否则 lib 打包报 not exported）
   - `scripts/check-exports.mjs` 的 `collectExports` 能识别 `export { ... } from`，故 barrel 校验不断链；下游 100+ 深层 import 全部不用改。
2. **`this` 耦合的方法块** → 新模块导出自由函数 `fn(scope: IXxxContext, ...)`、`scope` 用**结构化 context 接口**（只声明所需字段/方法，不 `import` 主类，避免运行时环）；类内保留 `method(a, b) { return fn(this, a, b); }` 一行委托。
3. **`import type` 优先**；新模块不得运行时反向 import 主类；需要主类类型时用 `import type` 或 context 接口。
4. **新模块自身也必须 ≤1000 行**（门禁判定 `lines.length > 1000`），否则拆分反而抬高 `giantFiles`。
5. **ESLint**：`@typescript-eslint/no-unused-vars: error`，搬移后必须清理原文件失效 import、补齐新模块 import。
6. **ratchet**：搬移不改变 `explicitAny`；新增 context 接口一律具体类型，不引入 `any`；新模块文件名不得含 ` copy` / `副本` / `.bak` 等（`backupNamedFiles` 正则）。
