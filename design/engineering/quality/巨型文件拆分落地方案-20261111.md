## 二、「一次完整 CI」的精确定义

`npm run ci`（package.json L48）**不含 `test:browser`**，而 `ci:no-e2e`（L49）含但不含 e2e。总方案 §2.6 已把「glTF 契约 66 项 browser 测试不在 `ci` 链路」列为缺口，而第 3 期恰好要拆 `gltf.ts`。因此定义：

```
完整 CI = npm run ci:no-e2e && npm run test:e2e
        = lint + check:quality + typecheck + test:run(92) + test:browser(73, 含 glTF 契约 66)
          + check:exports + build:lib + test:e2e(85, GPU 逐帧差值)
```

等价于 `npm run ci` 再补 `test:browser`。每次拆分提交都按此跑一遍。
e2e 默认 8 workers 已知偶发页面加载超时（总方案 §五 第 2 期记录）：若**仅**超时类失败，用 `npx playwright test --workers=4` 复验并在执行记录中注明；若出现截图差值，一律按缺陷处理。

## 三、通用拆分机制（零 API 漂移）

实测前提：`src/we` 全量扫描 `private|protected` 仅 3 个文件命中，这 8 个文件**内部 0 处**——所有成员都是 TS 默认 `public`。因此搬走实现后类内必须保留**同名同签名**的方法壳。

1. **类型/接口/枚举/常量/纯函数块** → 同目录新模块 `xxx.ts`；原文件用
   - `export { A, B } from './xxx'`（运行时值：enum / function / const）
   - `export type { C, D } from './xxx'`（interface / type，index.ts 头部注释明确要求分开，否则 lib 打包报 not exported）
   - `scripts/check-exports.mjs` 的 `collectExports` 能识别 `export { ... } from`，故 barrel 校验不断链；下游 100+ 深层 import 全部不用改。
2. **`this` 耦合的方法块** → 新模块导出自由函数 `fn(scope: IXxxContext, ...)`、`scope` 用**结构化 context 接口**（只声明所需字段/方法，不 `import` 主类，避免运行时环）；类内保留 `method(a, b) { return fn(this, a, b); }` 一行委托。
3. **`import type` 优先**；新模块不得运行时反向 import 主类；需要主类类型时用 `import type` 或 context 接口。
4. **新模块自身也必须 ≤1000 行**（门禁判定 `lines.length > 1000`），否则拆分反而抬高 `giantFiles`。
5. **ESLint**：`@typescript-eslint/no-unused-vars: error`，搬移后必须清理原文件失效 import、补齐新模块 import。
6. **ratchet**：搬移不改变 `explicitAny`；新增 context 接口一律具体类型，不引入 `any`；新模块文件名不得含 ` copy` / `副本` / `.bak` 等（`backupNamedFiles` 正则）。

### C2 附录 · newNode 循环引用分析与下一步改进路线

> 本节为取消 C2 后的**改进章程**，供后续独立专题使用；不属于第 3 期「等价搬移」范围。

**1. 循环引用形态（为什么直接搬会成环）**

当前 `nodeObject.ts:1056` 的 `newNode` 工厂：

```ts
export async function newNode(parent: NodeObject) {
    const scene: Scene = parent.scene;
    const node = new NodeObject();   // ← 工厂依赖具体类
    await node.init(scene, parent);
    return node;
}
```

调用点在 `model/gltf/function.ts:37/74`（`await newNode(parent)`）。若把工厂搬到 `nodeObjectFactory.ts`，链路变成 `nodeObject.ts → nodeObjectFactory.ts → nodeObject.ts`（`newNode` 内 `new NodeObject()` 需运行时 `import { NodeObject }`），形成**运行时循环依赖**；而 `index.ts` 又要求 `nodeObject.ts` 继续导出 `newNode`，进一步锁死这条环。类型块（`IV_Node` / `NodeObjectJSON` / `E_BVHSpaceType`）是纯 `interface`/`enum`，迁出无此问题。

**2. 改进手段（按推荐度）**

| 手段 | 做法 | 代价 |
| --- | --- | --- |
| A. `import type` 切断运行时边 | 工厂里 `new NodeObject()` 只需类型，写 `import type { NodeObject }`，编译后擦除，无运行时 import | 最小改动，保留拆分收益；但仍让 `nodeObject.ts` 经 re-export 单向依赖工厂 |
| B. 依赖注入（推荐） | `newNode(parent, NodeObjectClass)`，构造器由调用方传入，工厂文件零 import `nodeObject.ts` | 改了 `newNode` 公开签名，所有调用点要传 `NodeObject`，属重构 |
| C. 只搬类型块 | 94 行类型迁出，`newNode`（12 行）留原文件 | 最务实降级，`nodeObject.ts` 仍 >1000 行（不达标），但安全 |
| D. 声明式/数据驱动 | `NodeObjectJSON` 已描述结构，改为配置表 + 通用构造器，从根消除「工厂依赖具体类」 | 收益最大、代价最大，适合独立专题 |
| E. 不拆（本期已选） | 保留为巨型文件 | 短期最稳 |

**3. 依赖注入改造示例（手段 B）**

```ts
// nodeObjectTypes.ts（纯类型，不依赖 nodeObject.ts）
import type { Scene } from '../scene/scene';

export interface INodeObject {
    scene: Scene;
    parent?: INodeObject;
    init(scene: Scene, parent: INodeObject): Promise<void>;
}
export type NodeObjectConstructor = new () => INodeObject;   // 构造签名，不引用具体类
```

```ts
// nodeObjectFactory.ts（零运行时依赖 nodeObject.ts）
import type { INodeObject, NodeObjectConstructor } from './nodeObjectTypes';
import type { Scene } from '../scene/scene';

export async function newNode(
    parent: INodeObject,
    NodeObjectClass: NodeObjectConstructor
): Promise<INodeObject> {
    const scene = parent.scene as Scene;
    const node = new NodeObjectClass();      // 不再 new NodeObject()
    await node.init(scene, parent);
    return node;
}
```

```ts
// nodeObject.ts：类 implements INodeObject，newNode 改为再导出
export class NodeObject implements INodeObject {
    scene!: Scene;
    parent?: INodeObject;
    // ... 原有实现 ...
}
export { newNode } from './nodeObjectFactory';   // 保持 index.ts / function.ts 的 import 路径不变
```

```ts
// function.ts：调用方传入构造器
import { NodeObject } from '../organization/nodeObject';

const oneNode   = await newNode(parent,  NodeObject);
const childNode = await newNode(oneNode, NodeObject);
```

> **为何环断**：`nodeObjectFactory.ts` 对 `NodeObject` 仅 `import type`（编译擦除，零运行时边）；与 `nodeObject.ts` 唯一的运行时联系是 `nodeObject.ts` 的 `export { newNode } from './nodeObjectFactory'`（单向 re-export）；`NodeObject` 类本身由调用方 `function.ts` 传入。环被彻底打断。

手段 B 改了 `newNode` 的公开签名（多一个必填参数），所有调用点需同步改——已超出「等价搬移、行为零变化」前提，属重构。而 **C0 特征测试目前未覆盖 `nodeObject` 的运行时构造行为**（`nodeObject.test.ts` 只测 `NodeObject.update` 的 AABB 入 `Box3s`，未固化 `newNode`），改了签名却无测试兜底，风险不可控。故本期取消、留作独立专题。
