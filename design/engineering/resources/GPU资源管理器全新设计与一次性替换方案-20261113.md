## 一、决策与结论先行

### 1.1 为什么换路线

| 维度 | 旧：渐进式重构 | 新：旁路实现 + 一次性替换 |
| --- | --- | --- |
| 阶段 | Phase 0 ~ 5 共 6 期 | **3 阶段**（旁路实现 / 一次性切换 / 清理验收） |
| 完整 CI 次数 | 每期一次，共 ≥6 次 | **切换期 1 次**（旁路期不接生产，只需 `ci:no-e2e`） |
| commit 数 | ≥6 次 | 旁路期随意；**切换 + 清理 1 ~ 2 次** |
| 兼容层 | deprecated getter、`releaseLegacyMapList()`、`mapList` 过渡 | **全部取消**：调用点一次性适配，不背历史包袱 |
| 基线管理 | 逐期 `quality:baseline` 收紧 | 切换期**一次**收紧 |
| 回滚 | 逐期 `git restore` | **单行开关**切回旧实现；旧文件保留到最后一步才删 |
| 风险暴露 | 每期都有 e2e 判差值 | 风险集中在切换期，但旁路期可做到「新实现零生产影响」 |

**核心思路**：把「改造旧类」变成「在旁边写一个全新的、带完整测试的类」，验证通过后再把 `Scene` 的一行构造切过去，同步改完调用点，最后删旧文件。旧类在切换前**一行不动**，因此不存在「半重构状态」。

### 1.2 新方案一句话

在 `src/we/core/resources/gpu/` 新建一套**自包含**的 GPU 资源管理器（4 个 Store + 变种 key + 释放申请 + 帧级 tick + 完整单测），`Scene` 通过**单行开关**切换；切换同一次提交内完成全部调用点适配、删除 `mapList`、接入 `Scene.update()`、删旧实现；切换前旧代码零改动、随时可回退。

### 2.2 缓存判据（C1 ~ C3）

| 类别 | 判据 | 处置 |
| --- | --- | --- |
| **重·需编译** | VS / FS / CS `GPUShaderModule`、render / compute `GPURenderPipeline` | `DerivedCache`，按 C4 的三层 key 命中，精确失效 |
| **重·需释放** | `GPUTexture`、WE3D `Texture` | `AssetCache`，`refCount` + lease，归零才 `destroy()` |
| **轻·引用型** | `GPUBindGroup` / `GPUBindGroupLayout` / `*LayoutEntry` / `*BindingLayout` / BOL `I_pointerStruct` | **不进全局缓存**，下沉到 owner 局部 `WeakMap`（参照 `DrawCommandGenerator.ts:68` 的 `bindGroupLayoutIds`） |
| **轻·减少分配** | 3 个 preset sampler、`defaultPBR`、`oneStorageMatrix` | `DefaultResources` scene 单例，`counted=false`，常驻；仅在 `clean()`（退出 / 强制清空）时随全量清空一起处理 |
| **BOL 体系** | `GPUBuffer` 及 `I_pointerStruct` | 归 `BOL` / `BPC` / `Pointers`，`resourcesGPU` 不持有 |

### 2.3 四个 Store 契约

| Store | `K` | `V` | 所有权 / 失效 |
| --- | --- | --- | --- |
| `DefaultResources` | 固定常量 | `GPUTexture` / `Texture` / `BaseMaterial` / `GPUSampler` / `GPUBuffer` | scene lifetime，常驻；**不参与引用计数、不单独释放**，仅随 `clean()` 全量清空（退出 / 强制清空） |
| `AssetCache` | `string`（规范化） | `GPUTexture` / `Texture`（重）；`GPUSampler` / `BaseMaterial`（轻，`counted=false`） | `acquire → ticket`，`requestRelease → pending`，`tick` 裁决后 `disposeOf` |
| `DerivedCache` | `string`（`stage + MD5(finalWGSL)` / descriptor 版本） | `GPUShaderModule` / `GPURenderPipeline` / `GPUComputePipeline` | **必须命中**；无 `destroy()` API，`invalidate(key)` 精确失效后 `Map.delete`，随 device 生命周期回收；`stats()` 记账 |
| `SystemCache` | `string` / `GPUBindGroup` | `GPUBindGroup` / layout | 相机 / 灯光变化触发失效；`cleanSystemUniform()` 演化版 |

### 2.4 编译产物 key：三层契约（C4，最高优先级）

`finalWGSL` 的**唯一正确定义**（顺序不可变）：

```
finalWGSL = getGroupAndBindingString(materialType)                    // baseMaterial.ts:498/645
          + getAliasShaderName(aliasName, userCode, userFn)           // SHR/shaderRegister.ts:307-328（#replace 注入）
          + [VS only] reflection(..., DC_vertexNames, DC_localtions)  // DrawCommandGenerator.ts:579-583
```

| 层 | 字段 | 计算 | 作用 |
| --- | --- | --- | --- |
| ① 命中（唯一依据） | `finalCodeHash` | `MD5(finalWGSL)` | 防碰撞最后一道闸；**必须整条链完成后计算** |
| ② 变种标识 | `variantKey` | `aliasName + ':' + MD5(userCode + '\0' + userCodeFunction)` | 可读 / `stats()` 按变种统计 / 按变种精确失效 |
| ③ 反射签名 | `reflectionSignature` | `stableStringify({ names, locations, buffers, morphTargets, ndc, reflectionVersion, applied })`，列表保序、保留原始大小写 | VS 专属；`NDC === true` 跳过反射、占位符缺失时 `applied=false` 必须与 `true` 区分 |

**硬规则**：① 命中只用 `stage + finalCodeHash`（VS / FS / CS 分前缀，`fragment.code === undefined` 用 `stage='none'`，不复用空串）；② `variantKey` 与 `reflectionSignature` 写入条目并**进入 pipeline `keyObject`**（在现有 `DrawCommandGenerator.ts:763-784` 的 12 个字段上追加这 2 个）；③ 禁止 `aliasName` / 模板 code 单独作 key；④ `shaderRegister.ts:359-362/379-382` 占位符缺失由 `console.log` 改 `throw`（或 `applied=false` 且不缓存）；⑤ CS / compute pipeline 同样适用。

### 2.5 释放申请 + 可插拔策略（C5）

```
RootGPU 派生类:
  const { value, ticket } = resourcesGPU.assets.textures.acquire(source, factory)
  this.track(ticket)                          // 只保存不透明凭证
  destroy():
    resourcesGPU.requestRelease(ticket)       // 只提交申请
    this._destroy()                           // 只做自身状态 + manager 注销
    this._manager?.remove(this)
  // 派生类中不得出现: Map 名 / E_resourceKind / getProperty / Map.delete / GPU 对象 destroy()

ResourceManagerOfGPU（唯一决策者）:
  requestRelease(ticket) → 登记到 pendingReleases，不立即释放
  tick(clock)            → 每帧按 IV_ReleasePolicy.shouldRelease() 裁决，通过才 disposeOf + Map.delete
  clean()                → 全量清空（仅「退出」或「显式强制清空」两种情形调用）
  // 无 Scene.dispose()、无事件联动清空；资源与 resize / GBuffer 无关
```

`IV_ReleasePolicy` 由 `ResourceStore` 构造注入，默认 `RefCountPolicy`，可切 `LruPolicy` / `ImmediatePolicy` / 延迟 GC；**替换策略不改任何派生类一行代码**。

### 2.6 帧级 tick 与必须新增的基础设施（C6）

核实结果：`Clock`（`scene/clock.ts`）只有 `timeLast/timeNow/timeStart/_deltaTime/_deltaTimeMS/now/last/deltaTime`，**没有帧号**。`Scene` 没有 `dispose()` / `destroy()`，且**本次不新增** —— `scene.ts:643-668` 的 `reSize()` 只处理 `finalTarget` 颜色 / 深度纹理（render target / GBuffer 体系），与资源缓存无关，不能作为释放入口或参考。因此替换步骤只包含两处新增：

| 新增 | 位置 | 内容 |
| --- | --- | --- |
| `Clock.frame` | `scene/clock.ts` | 新增 `frame: number = 0`；`update()`（`:46-53`）内 `this.frame++`。给 pending 延迟一帧判定与 LRU TTL 提供确定性帧号（也可用 `clock.now`，但帧号便于单测） |
| `Scene.update()` 末尾 | `scene.ts:828` 之后 | 新增 `this.resourcesGPU.tick(this.clock)`（用户指定插入点） |

> **`Scene` 不参与资源释放**：不新增 `Scene.dispose()`，也不在 `reSize()` / `cleanUp()` 中触发资源清空。资源缓存常驻，与 resize、IBL 变化、GBuffer 重建无关。

**帧循环时序风险**（`scene.ts:849-873`）：`update()` 之后还有 `onAfterUpdate → onBeforeRender → render → onAfterRender → showGBuffersVisualize → renderToSurface → cleanUp`，渲染阶段仍会创建 / 使用 shaderModule、pipeline、纹理。故 `tick()` 采用**延迟一帧**：

| 阶段 | 动作 |
| --- | --- |
| ① 申请 | `requestRelease(ticket)` → `{ ticket, frameRequested: clock.frame }` 入 `pendingReleases`，条目标 `releasable=true` |
| ② 使用检查 | `acquire(key)` 命中已标记条目 → 撤销申请（移出 pending、`releasable=false`、`lastUsedFrame = clock.frame`） |
| ③ 每帧裁决 | `tick(clock)` **只遍历 `pendingReleases`** 且只处理 `frameRequested < clock.frame` 的条目；逐条问 `shouldRelease(entry, clock)` |
| ④ 释放 | 通过 → `disposeOf(value)` + `Map.delete(key)` + 移出 pending；单帧最多 `maxReleasesPerFrame` 条，超出顺延 |
| ⑤ 全量清空 | `clean()` 为**全量清空**，仅在「退出」或「显式强制清空」两种情形被调用；resize / IBL 变化 / `dispose()` **均不触发**；不是主路径，主路径是每帧 `tick()` |

复杂度 **O(pendingReleases)**，不扫描全部分区；这是每帧可行的前提（对应风险 R7）。

> **`clean()` 触发契约（用户 2026-11-13 修正）**：资源缓存与 resize、IBL 变化无关，`Scene` 也没有资源释放入口。**只有退出或显式强制清空才调用 `clean()`**；descriptor 因 resize / IBL 变化时，编译产物由 `invalidate(key)` 精确失效，或由 key 中的 descriptor 版本自然区分出新条目，**不做全量清空**（C7）。`clean()` 清空时按分区 `disposeOf` 处理可 `destroy()` 的重资源，编译产物只删 Map 条目（无 `destroy()` API）。

### 2.8 关键接口签名草图

```ts
// types.ts
export type T_cacheId =
    | 'textures' | 'weTextures' | 'shaderModules' | 'pipelines'
    | 'samplers' | 'materials';

export interface IV_ReleaseTicket { readonly id: number; readonly released: boolean; }
export interface I_AcquireResult<V> { value: V; ticket: IV_ReleaseTicket; }
export interface IV_ResourceEntry<V> { value: V; refCount: number; releasable: boolean; lastUsedFrame: number; }
export interface IV_ReleasePolicy<K, V> {
    shouldRelease(entry: IV_ResourceEntry<V>, clock: Clock): boolean;
    onAcquire(entry: IV_ResourceEntry<V>): void;
    onSweep(entries: Iterable<[K, IV_ResourceEntry<V>]>): void;
}

// resourcesGPU.ts（新类）
export class ResourceManagerOfGPU {
    readonly defaults: DefaultResources;
    readonly assets: AssetCache;
    readonly derived: DerivedCache;
    readonly system: SystemCache;

    requestRelease(ticket: IV_ReleaseTicket): void;      // 只登记
    tick(clock: Clock): void;                           // 每帧裁决 O(pending)
    invalidate(kind: 'shaderModules' | 'pipelines', key: string): void;  // 精确失效，无全清
    clean(): void;   // 全量清空：仅「退出」或「显式强制清空」调用；不由 resize/IBL/dispose 等事件触发
    stats(): Record<string, { size: number; totalRefs: number }>
        & { pendingReleases: number; releasedThisFrame: number };
}
```

## 七、风险与回滚

| # | 风险 | 概率 | 影响 | 缓解 | 回滚 |
| --- | --- | --- | --- | --- | --- |
| R1 | 一次性切换漏改调用点 | 中 | 运行时 `undefined` / tsc 报错 | Step 1 用 `tsc` 错误清单反查附录 A；每批 `tsc` 收敛；`check:exports` 兜底 | 开关改 `false`（Step 1~4）或 `git revert` 切换 commit |
| R2 | 变种 key 撞车（把 `code` 取成模板文本 / 只用 `aliasName`） | 中 | **极高**：渲染错乱或全黑（`gltf-transform-phase4-plan.md:390-394` 实证） | §2.4 三层 key；Stage 1 变种矩阵 + `keyObject` 值快照；反射失败改 `throw` | 回退 `shaderVariantKey.ts` 接入，恢复 `MD5(最终 code)` 行为 |
| R3 | 共享资源被策略提前释放，暴露悬挂使用 | 高 | WebGPU validation error | 默认 `RefCountPolicy`；`tick` 延迟一帧；真实 device 单测 | 临时切「只登记不释放」策略；必要时显式 `clean()` 强制清空后重建 |
| R4 | 每帧 `tick()` 退化为全表扫描 / 集中释放帧尖峰 | 中 | 帧率抖动 | 只扫 `pendingReleases`（O(pending)）、`maxReleasesPerFrame`、帧耗时基准断言 | `tick()` 降级为只登记 |
| R5 | 删 `mapList` 破坏 `RootGPU` 公共类型形状 | 中 | 下游 / typedoc 漂移 | 一次性适配 + `docs/` 由 release 重建 + `design/workBuddy/core/*` 同步 | `git revert` |
| R6 | 补齐 CS / compute 缓存或修共享销毁导致 e2e 差值 | 中 | 基线失败 | §3.3 差异清单预先评审；判差值规则写死 | 预期变化才 `test:baseline` 同提交；否则修适配重跑 |
| R7 | 质量基线未随删除旧文件收紧 | 低 | ratchet 失效 | Step 6 固定 `quality:baseline` 且同提交 | 补跑并新 commit |
| R8 | `Clock.frame` 新增影响其它子系统 | 低 | 帧号语义冲突 | `frame` 只自增、不改现有时间字段；**不新增 `Scene.dispose()`**，`Scene` 不参与资源释放；`reSize()` 的 `finalTarget` 属 GBuffer 体系，不改动 | 单独 revert `Clock.frame` |

**总回滚**：Stage 0/1 旧代码零改动，天然无风险；Stage 2 的 Step 1~4 期间旧文件仍在、开关可切回；Step 5 之后用 `git revert <切换 commit>` 整体回退到 Stage 1 锚点。符合 `AGENTS.md` §三.2「先让构建变绿 → 建回归基线 → 加单测 → 再修错误」。
